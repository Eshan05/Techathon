# Kisan Vakil — Data Model (MVP + roadmap)

This document outlines the **minimum required tables** for the MVP and the **recommended expansion tables** for the full “Kisan Vakil” product.

## Principles

- **Trust-first**: every record should have `createdAt` (and usually `updatedAt`) for auditability.
- **User-owned**: tables are scoped by `userId` (Better Auth `users.id`) and enforced in APIs.
- **Offline friendly** (future): drafts should be storable locally and syncable server-side.

---

## MVP (implemented)

### 1) `farmer_profiles`
One profile per user (PK = `userId`). Used for language, location defaults, and pre-filling templates.

Suggested fields:
- `userId` (PK, FK → `users.id`)
- `fullName`, `phone`
- `preferredLanguage` (e.g. `hi`, `mr`, `pa`)
- `supportNeed` (e.g. `land-records`, `schemes`, `notices`)
- `trustedHelperName`, `trustedHelperPhone`
- `state`, `district`, `tehsil`, `village`
- `createdAt`, `updatedAt`

### 2) `land_parcels`
Stores the farmer’s parcels and the identifiers typically needed for land-record lookup.

Suggested fields:
- `id` (PK, UUID)
- `userId` (FK → `users.id`)
- `nickname`
- `state`, `district`, `tehsil`, `village`
- `khataNo`, `khasraNo`, `mutationNo`
- `ownerName`, `ownershipShare`
- `notes`
- `createdAt`, `updatedAt`

### 3) `documents`
A lightweight “vault index” for uploaded items (UploadThing), optionally linked to a land parcel.

Suggested fields:
- `id` (PK, UUID)
- `userId` (FK → `users.id`)
- `title`, `kind` (e.g. `sale-deed`, `khata`, `court-notice`, `id-proof`)
- `uploadthingKey`, `url`
- `mimeType`, `sizeBytes`, `sha256`
- `landParcelId` (nullable FK → `land_parcels.id`)
- `issuedAt` (nullable)
- `createdAt`

## Roadmap (recommended next tables)

### Land record lookups
- `land_record_requests` — parameters used for lookup (state/district/khata/khasra), status, provider.
- `land_record_snapshots` — normalized ownership history + raw JSON from the source.

### Templates (legal notices, complaints, RTI, affidavits)
- `templates` — curated template library (multi-language), versioned.
- `template_runs` — generated output, variables used, delivery/export status.

### Grievances & complaints
- `grievances` — category (electricity/irrigation/procurement/revenue), status, target department.
- `grievance_events` — timeline events, reminders, acknowledgements.

### Case tracker
- `cases` — forum/court, case number, parties, stage, next hearing.
- `case_events` — hearing dates, orders, tasks, reminders.

### Scheme eligibility
- `schemes` — scheme definition + rules.
- `scheme_checks` — user inputs, eligibility result, explanation in plain language.

### Expert chat
- `conversations` — conversation metadata (language, topic).
- `messages` — user/assistant messages, attachments, summaries.
- `conversation_summaries` — periodic summaries for long threads.

### Evidence capture
- `evidence_items` — photo/video, geo/timestamp, hash, chain-of-custody notes.
